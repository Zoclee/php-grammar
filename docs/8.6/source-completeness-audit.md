# PHP 8.6 source correspondence and completeness audit

October 24, 2026. **Phase 6 audit completed with unresolved completeness
blockers. PHP 8.6 remains draft.** This is an audit result, not a finding that
the grammar is complete, release certification, or authorization to begin
Phase 7. No normative grammar, specification, lexer, fixture, public interface,
manifest, historical evidence or release gate was changed.

## Evidence method and limits

The [independent ledger](source-completeness-ledger.json) is generated by
[PHP audit tooling](../../tools/8.6/source-completeness-audit.php). It freshly
parses both upstream grammars, uses the existing action-aware Bison branch
splitter, indexes canonical EBNF identities using the repository parser, and
joins independently measured coverage with reviewed parser anchors. It retains
every upstream RHS and action-call identity, all scanner headers and states,
all canonical identities, all 578 compiler hunk identities, 73 inherited
restriction descriptions and 59 RFC candidates. Input hashes and references
avoid copying existing fixture/source records into a second authority.

There are deliberately two correspondence levels: a reviewed canonical
production anchor, and a broader section/family association. Neither proves
individual branch equivalence. The latter is explicitly weaker and retains
an individual-mapping obligation. Identical C text establishes textual
continuity, not unchanged transitive behavior. No generated association is
silently promoted to semantic proof or an instrumented rule hit.

The audit covers the complete enumerated inventories. It does not pretend to
finish every outstanding compiler discovery review. Every residual material
group remains identified and blocking where appropriate; see the
[machine-readable dispositions](source-audit-dispositions.json).

## Parser correspondence

The fresh inventory confirms **176 upstream productions and 623 alternatives**.
The older PHP 8.5 inventory has 177 productions because `backup_lex_pos` is an
empty metadata helper removed from RC4. No source terminal is lost with it.
There are **167 identical RHS/action bodies and nine changed bodies**.
Token, precedence and associativity declarations compare identically.

| Changed body | Source-backed disposition |
|---|---|
| `argument_list`, `non_empty_argument_list` | PHP86-001 argument-list/placeholder AST construction; ordinary and callable lists converge in the implementation. |
| `clone_argument_list`, `non_empty_clone_argument_list` | PHP86-001 keeps clone-specific expression ambiguity boundaries and uses the new argument-list helpers. |
| `argument_no_expr` | Required `?`, named `?` and variadic `...`; existing unpacked expression retained. No optional `?=` placeholder. |
| `parameter` | PHP86-009 moves empty doccomment capture after the default; metadata attachment, not new terminals. |
| `trait_method_reference`, `absolute_trait_method_reference` | AST kind rename; unchanged source RHS. |
| `inline_function` | Empty lexical-position bookkeeping removed; closure/arrow terminals and function-flag handling retained. |

Every parser production maps to canonical anchors or an explicit metadata
abstraction. Recursive lists become EBNF repetition/options; source tags and
HTML use scanner/adapter behavior. The `inner_statement` halt alternative is
an error path, not permission for nested halt directives. Parser-action
modifier failures remain distinct from context-free reductions.

The expression family retains low-precedence include/print/throw/arrow/yield,
assignment, conditional/coalesce, logical, comparison, pipe, concatenation,
arithmetic, power and prefix distinctions. Unchanged declarations support
continuity of precedence/associativity; they do not prove the chart matcher's
AST binding. Matched/unmatched statement helpers represent dangling-else
resolution. Closed-yield/prefix helpers represent operand-boundary interactions.
Existing integration/coverage witnesses support these transformations; isolated
binding and upstream-alternative coverage remain C6-COVERAGE obligations.

Calls, constructors, clone, references, types, attributes, namespaces/imports,
class/interface/trait/enum bodies and hooks retain individual production-family
rows. PFA has fresh paired evidence. Shared declaration bodies intentionally
leave target legality to later compilation/linking. The explicit get/set-only
hook rule remains the documented **CA86-001 divergence**, not parser equivalence.

## Scanner correspondence

The inventory independently reproduces **190 rule headers and 11 states**.
Headers retain their order and text across the pins. All 190 are associated
with the existing lexer implementation/family inventory and the RC4 source
range. PHP 8.6 selects its own version identity with the retained keyword set.

The 51 Phase 5B/5E source/profile entries associate with **34 rule ranges** by
source-range overlap. The other **156** have inherited family evidence without
an established isolated RC4 rule witness in that matrix. An entry can refer to
several rules or a helper outside the rule inventory. Range overlap does not
prove execution. **There is no defensible instrumented scanner-coverage
percentage here.** Earlier integration entries and inherited scanner tests
remain separate evidence, not a silently increased numerator.

| Family | Correspondence and remaining obligation |
|---|---|
| Tags, HTML, comments, attributes | Lexer/adapter implements source transitions, short-tag profiles and comment boundaries. Attribute versus hash comment remains state-dependent. |
| Identifiers, names, keywords | Byte spelling and token category differ; property lookup, enum lookahead, qualified names and composite yield-from require context. |
| Numeric literals | Spelling, overflow category and offset-state numeric strings are distinct; byte-boundary evidence is retained. |
| Strings/escapes/interpolation | Repository tokens aggregate Zend fragments. Native token-boundary comparison is deliberately not asserted for aggregated strings. Unicode validation may occur after raw tokenization. |
| Heredoc/nowdoc | Label, indentation, lookahead and recursive state behavior are external scanner contracts. Ordinary and malformed witnesses do not exhaust error-state interactions. |
| PFA | Existing `?` and `...` tokens; new parser/AST use, not a new scanner pattern. |
| State/context feedback | Property, variable-name, offset, nested scripting and heredoc return states remain explicit. Parser metadata and halt behavior cannot be reduced to character-only EBNF. |

The scanner helper review retains the prior full-diff findings: AST compilation
extraction, TLS/line-counter changes, redundant length-cast cleanup and heredoc
exception save/restore changes. The balanced-function inventory identifies
15 named scanner functions, 11 text-identical; macro/state rules are separately
enumerated. `zend_scan_escape_string`, indentation/newline handling, nesting/EOF
diagnostics, encoding filters and heredoc lookahead remain necessary supporting
paths. Reentrant compilation with an existing exception, recursive state/error
products, ZTS and multibyte conversion are not certified. Header equality alone
does not discharge those obligations.

## Compiler and contextual correspondence

The ledger relocates all **73 inherited restriction descriptions** to current
source-family entry points and normative clauses. Related PHP86 findings link
to hashed local fixtures and immutable source/test records. These are
restriction descriptions, not 73 independently isolated RC4 predicates.
In particular, the inherited label mentioning readonly defaults must be read
with the PHP86-003 relaxation, not copied as an unchanged prohibition.

| Area | Pinned implementation and evidence boundary |
|---|---|
| Parser actions/modifiers | Modifier conversion/list helpers run before folding; target/duplicate/conflicting modifiers are not all enforced by structural matching. |
| Types/functions/parameters | Typename, parameter and function compilation enforce positional types, promotion, references, captures and return/generator restrictions. Predicate-specific evidence remains incomplete. |
| Properties/hooks | Property and hook compilation plus inheritance checks; PHP86-003 defaults do not relax typing/static/hook restrictions. Unknown discarded hook remains CA86-001. |
| Attributes/constants/linking | Attribute target flags, constant compilation and inheritance implement PHP86-005; missing Override targets can survive lint and fail declaration linking. |
| Enums | Enum compilation, magic-method validation and linking implement PHP86-006; signatures, warnings and delayed value checks stay separate. |
| Writable/reference expressions | `zend_can_write_to_variable`, delayed fetches and list/reference handling support PHP86-004/007; assignment-result dispatch remains PHP86-014. |
| Constant evaluation/AST | AST argument helpers and compiler constant traversal distinguish parsing, visited/discarded AST, surviving-node legality and optimized dispatch. PHP86-015 remains unresolved. |

Fresh changed-rule matrices and the 81-source discrepancy matrix support these
bounded conclusions. The matcher does **not** implement a complete contextual
validator. Structural acceptance of a contextual negative is expected evidence,
not a test failure to suppress or proof of source validity.

Across scanner/compiler/AST/inheritance/attribute/enum/constant source, the
named-function inventory retains line locations and body hashes. It is not a
complete call graph: macros, indirect dispatch and transitive effects remain
outside its mechanical guarantee.

## Production and alternative completeness

Fresh measurement reproduces **297/361 productions (82.27%)** and
**482/800 alternatives (60.25%)**. Every identity has an explicit correspondence
granularity, coverage reference, risk and remaining obligation.

| Audit classification | Productions | Alternatives |
|---|---:|---:|
| Source-corroborated at direct production-family anchor, covered | 160 | 232 |
| Covered, broader family correspondence only | 137 | 250 |
| Source-corroborated at direct production-family anchor, unexercised | 1 | 109 |
| Unexercised, broader family correspondence only | 0 | 25 |
| Context-dependent lexical abstraction | 63 | 183 |
| Unresolved | 0 | 1 |
| Total | 361 | 800 |

“Source-corroborated” here does not mean every alternative has an isolated
upstream derivation. No unreachable/redundant production was established, and
no production was removed. The 64 unexercised productions comprise 52
primitive-bypassed, 11 trivia-removed and `reserved-non-modifiers`. The 318
unexercised alternatives comprise 174 primitive-bypassed, nine trivia-removed,
134 meaningful gaps and one unresolved identity. These remain the original
coverage classifications; the audit adds correspondence rather than changing
the denominator.

Highest-value obligations are:

1. Reserved token/category matching, especially the context-only `from`
   alternative (`reserved-non-modifiers/alternative:25`); do not silently count
   composite-token behavior as independent keyword coverage.
2. Namespace/type/declaration alternatives, modifier targets and their
   positive versus parser-action/compiler rejection boundaries.
3. Dynamic class/member/dereference/constructor and callable forms with nearby
   invalid targets; PFA/constant-expression interactions.
4. Closed-yield/prefix and matched/unmatched control-flow alternatives with
   operand-span or AST evidence, rather than acceptance-only witnesses.
5. Lexical primitive bodies through scanner/state tests; ordinary chart coverage
   cannot exercise a body intentionally bypassed by the token adapter.

Low coverage does not prove incorrect syntax. Conversely, coverage plus family
mapping does not establish grammar completeness. No arbitrary percentage target
replaces these obligations.

## Version differences and changes.md

The fresh [traceability check](source-audit-traceability.json) finds exactly
five modified productions, zero additions and zero removals:
`ordinary-argument-list`, `first-class-callable-arguments`, `clone-argument-list`,
`argument`, and `argument-no-expression`. All are mapped to PHP86-001.
All ten required changes.md sections and 14 reviewed documentary sections
remain accounted for, including PHP86-003 through PHP86-007, warning-only
PHP86-010 and the informative PHP86-014/015 scope clarifications.

The existing validator compares parsed node structure, including alternative,
optional, repetition, terminal and reference changes; verifies baseline and
reviewed hashes, production/test/source mappings, documentary changes and
parity. Its negative tests cover invented alternatives, added/removed
productions, stale/missing evidence, missing sections/identifiers and lexical
configuration changes. They pass in the full suite.

The validator cannot discover an unrecorded upstream contextual change merely
because EBNF is unchanged. Reviewed prose hashes establish change control,
not semantic correctness. Therefore **all currently implemented mapped
differences are accounted for; all possible PHP 8.6 differences are not yet
proven accounted for**. PHP86-013 prevents the stronger claim.

## PHP86-014/015 and inherited-hook dispositions

Fresh public issue/review comments were retrieved for upstream PRs 20628 and
19658: **17 + 15** and **8 + 15** comments respectively, within a first-100
bounded request per endpoint. The [snapshots](source-audit-upstream.json)
preserve URLs, dates, bodies and raw-response hashes. This is not an exhaustive
upstream issue search.

PR 20628 discusses faulty assertions, reference passing of `new`, VM handlers
and related runtime fixes. It supplies no exact-form intended-validity decision
for the assignment-derived writes at issue. The pinned compiler/VM inconsistency
and fresh invalid-opcode observations remain evidence of an implementation
defect, not authority for a grammar prohibition or permission. **PHP86-014
remains unresolved, bounded and blocking.**

PR 19658 discusses printf optimization, constant collection and opcode
optimization. It does not settle a universal language rule for discarded casts.
Current Phase 5D wording correctly scopes the historical table and describes
visited-AST/dispatch observations informatively. **PHP86-015 remains unresolved,
bounded and blocking.** No function-specific grammar is proposed.

For **CA86-001**, the parser accepts an identifier as a hook name, compilation
validates get/set, and folding can discard the declaration first. The canonical
grammar intentionally restricts names earlier. Existing prose describes this
accurately. Its PHP 8.5 historical disposition is not automatic permission to
claim PHP 8.6 parser equivalence or certify the limitation without review.

## Confirmed defects, proposed corrections and blockers

No new independently verified normative EBNF/specification defect was established
by this audit. The known compiler/VM mechanism defect and hook-policy divergence
remain explicit. Absence of a newly confirmed defect is not a completeness claim.

The [disposition ledger](source-audit-dispositions.json) records affected
constructs, authoritative/missing evidence, correctness risk, draft/candidate/
stable impact, priority, remediation and certification effect for PHP86-013,
PHP86-014, PHP86-015, CA86-001, C6-CONTEXT, C6-COVERAGE and C6-PROVENANCE.
None is relabeled an accepted release limitation merely to declare readiness.

Priority P0 is material discovery. P1 is exact-form intended-validity evidence,
contextual predicate isolation, binding/scanner obligations and executable
provenance. Any writable/traversal correction needs its own Gate B source,
production/clause, stage, positive/negative and version-boundary contract.
The possible P2 hook correction is narrowly `hook-name` identifier acceptance
plus compilation-time validation, **only after** a separate policy decision and
historical-correction authorization. Live/discarded declarations and both
versions require regression evidence. No correction is implemented here.
